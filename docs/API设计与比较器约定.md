# API 设计与比较器约定

本文件是新增数据结构与算法的统一契约。目标不是让所有旧类型一次性改成同一种外观，而是让新 API 可预测，并在迁移旧代码时保持兼容。

## 1. 参数验证

- 公共引用参数使用 `ArgumentNullException.ThrowIfNull`，让参数名准确进入异常。
- 数字必须满足范围时使用 `ArgumentOutOfRangeException`，例如容量、概率、权重或启发值。
- 参数类型正确但组合不合法时使用 `ArgumentException`，例如遍历序列不一致。
- 对象当前状态不允许操作时使用 `InvalidOperationException`，例如空队列出队、负环导致最短路无定义。
- 查找一个按契约必须存在的键失败时使用 `KeyNotFoundException`。

为什么区分异常类型：调用方可以区分“参数本身错误”“对象状态错误”和“数据不存在”，测试也能更精确地表达契约。

## 2. 区间统一为半开形式

公开范围方法使用 `[start, endExclusive)`：

- 长度直接是 `endExclusive - start`。
- 空区间是 `[x, x)`。
- 相邻区间 `[a, b)` 与 `[b, c)` 不重叠。
- 与数组切片、`Span<T>` 和 .NET Range 的思维一致。

只有数学上没有空区间单位元的结构才拒绝空查询。例如 Sparse Table 的 Min 查询拒绝空区间；区间求和的单位元是 0，所以懒标记线段树允许空查询并返回 0。

## 3. 相等与排序

哈希结构接收 `IEqualityComparer<T>`；有序结构接收 `IComparer<T>`。二者不能混用：

- 哈希表要求 Equals 相等的键必须产生相同哈希码。
- 有序集合以 `Compare(x, y) == 0` 判断重复，与 `SortedSet<T>` 一致。
- 比较器由构造函数注入并通过只读属性公开，整个对象生命周期内不能替换。

红黑树与跳表实现 `IOrderedSet<T>`。接口只包含真正可互换的集合能力，不暴露树高、跳表层数等实现细节。

旧 BST/AVL 的 `IComparable<T>` 约束暂不删除，因为那会破坏调用方泛型约束和构造方式。迁移时应先加入比较器重载、通用契约测试和弃用说明，而不是直接修改公开签名。

## 4. 重复值与修改返回值

- 集合的 `Add`/`Remove` 返回 bool，表示状态是否真的改变。
- 映射的 `TryAdd` 拒绝覆盖，索引器赋值负责新增或覆盖。
- 图的重复边不是无声无操作：`WeightedGraph.AddEdge` 抛异常，避免调用方误以为权重已更新。
- 容量网络拒绝自环，因为自环不增加 s-t 流量，保留它只会复杂化成对残量边的索引契约。
- 需要更新边权时应提供语义明确的 `UpdateEdge`，而不是让 Add 同时承担两种含义。

为什么返回 bool：调用方不必先执行 Contains 再修改，避免重复搜索，也能直接写差分测试。

## 5. 输入与输出所有权

- 方法若会原地修改输入，名称、参数类型或 XML 注释必须明确说明。
- 只读算法优先接收 `IReadOnlyList<T>`、`IEnumerable<T>` 或 `ReadOnlySpan<T>`。
- 返回集合默认不暴露可修改的内部数组或列表。
- `Span<T>` 是借用视图，不能跨 async/iterator 生命周期保存。
- 从 `ArrayPool<T>` 租出的数组必须在 finally 归还；可能含敏感数据时清零。

Dinic 在容量网络的克隆上修改残量边，原因正是原始网络属于调用方；连续求流不应继承上一次的残量状态。

## 6. 数值契约

- 图权重、容量和启发值拒绝 NaN/Infinity，因为比较和加法无法维持算法不变量。
- Dijkstra/A* 拒绝负边；Prim 可以接受负边；Floyd/Bellman-Ford 接受负边但必须检测负环。
- 累计和使用 long，并在教学实现关键位置使用 `checked`，让溢出显式失败。
- 浮点残量比较使用小 epsilon，避免多次减法留下极小正数造成无效递归。

## 7. 可选诊断不污染核心算法

算法追踪通过可选 `IAlgorithmTraceSink` 注入。没有 sink 时不创建事件；有 sink 时记录结构化操作与状态。算法层不直接写控制台、不序列化 JSON，也不引用 Demo 项目。

不变量方法用于测试和学习，命名为 `HasValidInvariants`。它们可以是 O(n)，不能让调用方误以为适合每次生产操作后执行。

## 8. 测试与性能证据

新增模块至少应有：

1. 一个可手算的正常例子。
2. 空输入、单元素、重复值和边界数值。
3. 非法参数与非法状态。
4. 与标准库、朴素模型或另一算法的差分测试。
5. 状态型结构的不变量或长操作序列。
6. 只有声称性能收益时才加入 BenchmarkDotNet 基准。

覆盖率只说明执行过，变异测试进一步检查断言能否发现逻辑变化；两者都不能取代正确性推导。性能基准只比较成本，也不能证明结果正确。

## 9. C# 14 写法边界

- 使用集合表达式 `[]`、`[a, b]` 和扩展元素减少样板代码，但在重载可能歧义时写出显式类型。
- 使用主构造函数表达只负责保存参数的私有 Node/Entry；公共复杂类型仍优先显式构造函数，便于验证参数和写 XML 文档。
- 使用模式匹配表达互斥边界，例如 `value is < 0 or > 1`。
- 保持可空引用类型启用，不用 `!` 隐藏未证明的空值；只有结构不变量已经保证非空的局部位置才使用 null-forgiving。
- 不为追求“新语法”牺牲算法不变量的可见性。清楚的循环和局部变量通常比高度压缩的 LINQ 更适合核心热路径。
