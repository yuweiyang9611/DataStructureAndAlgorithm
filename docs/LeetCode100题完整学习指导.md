### 3.1 为什么原地题常用读写指针

26、27、75、88 都要求把答案写回原数组。真正删除元素会反复移动数据，可能变成 O(n²)。读指针负责检查，写指针只在确定答案后前进，可以把每个元素的写入次数限制为常数。

以 27 为例：

```text
read 扫描全部元素
write 指向下一个保留位置
[0, write) 永远是已经确认的答案
```

C# 中不能用 `foreach` 枚举 `List<T>` 的同时通过索引写入，因为索引 setter 会更新集合版本。本项目显式使用 `for`，注释说明这个运行时规则。

### 3.2 为什么矩阵题先验证形状

C# 的 `int[][]` 是锯齿数组，不保证每行等长，也允许某行是 null。LeetCode 输入通常满足矩形约束，但教学库的公共 API 会先验证，避免算法中出现难以理解的越界异常。

### 3.3 常见错误

- 31 只交换枢轴却不反转后缀。
- 33 把普通二分的判断直接套在旋转数组上。
- 73 在完成标记前就清零，导致零扩散到不应清零的位置。
- 88 从头合并，覆盖 first 中尚未读取的值。
- 128 对每个数都向两侧扩展，退化为 O(n²)。
- 169 只返回候选却不验证输入确实存在多数元素。

### 4.1 为什么 5 和 647 都使用中心扩展

两题的差别只在聚合方式：5 维护最长区间，647 每成功扩展一次就计数。中心扩展比枚举所有子串再反转验证少一层循环，并自然覆盖奇数与偶数长度。

### 4.2 为什么 438 不每次比较两个字典

若每移动窗口一次就完整比较频次表，会把复杂度乘上字符集大小。项目维护 `missing`：加入一个仍缺少的字符时减一，移除后重新缺少时加一。`missing == 0` 就是充分条件。

### 4.3 C# 字符与 Unicode

这些题遵循 LeetCode 常见的 `char` 语义。`char` 是 UTF-16 code unit，不一定等于用户看到的一个字符。真实国际化文本需要考虑 `Rune`、组合字符、Normalization 和文化相关大小写规则。

### 5.1 dummy 节点为什么重要

19、23、24、25 都可能改变链表头。没有 dummy 时，头节点需要单独分支；dummy 把“头前驱”变成真实节点，让删除、接入和交换统一为修改 `before.Next`。

### 5.2 为什么查询后要恢复链表

234 的目标是判断而非变换。如果反转后半段后直接返回，调用方得到的链表会被截断或改变。教学实现再次反转恢复，强调公共 API 的副作用契约。

### 5.3 节点身份与节点值

环入口、链表相交和 Random 指针都依赖节点引用身份。两个值相同的节点并不是同一个节点，因此测试使用 `Assert.Same` / `ReferenceEquals`。

### 6.1 树递归先写“返回值含义”

树题最容易写出能跑但无法证明的递归。动手前先写一句：

- 104 返回“当前子树高度”。
- 124 返回“可以向父节点继续延伸的单支最大和”。
- 543 返回高度，但用全局变量记录左右高度之和。
- 437 返回“当前子树内满足目标的路径数量”。

返回值含义固定后，递归组合通常自然出现。

### 6.2 297 为什么必须保存空节点

只有前序节点值无法区分“左孩子为空”和“右孩子为空”。`#` 标记把树形结构编码进序列，使反序列化可以唯一恢复。

### 7.1 回溯为什么必须撤销

39、46、79、797 共享模板：选择 → 递归 → 撤销。`selected`、`used`、`visited` 和 `path` 都属于当前递归路径；如果不撤销，兄弟分支会继承不属于自己的状态。

### 7.2 994 为什么是多源 BFS

若对每个腐烂橘子分别 BFS，会重复扫描。把所有初始腐烂位置同时入队，相当于添加一个虚拟超级源点。每一层统一表示经过一分钟，第一次感染就是最短时间。

### 7.3 133 为什么不能只按节点值去重

图节点值未必唯一，边连接的是对象身份。副本映射使用节点引用作为键，保证即使多个节点值相同也能正确克隆拓扑。

### 8.1 55 为什么贪心足够

题目只问能否到达，不问最少跳数或具体路径。对每个可达位置更新最远边界即可；在最远边界内的所有具体跳法对未来的贡献都被一个最大值概括。

### 8.2 84 为什么要加虚拟零高度

递增到数组结尾的柱子没有自然的更矮右边界。循环末尾加入高度 0 的虚拟柱，可以统一触发所有剩余柱出栈，不需要额外清栈代码。

### 8.3 209 为什么要求正数

正数保证右边界扩张时 sum 不减，左边界收缩时 sum 不增。如果允许负数，窗口和失去单调性，滑动窗口可能错过答案，应改用前缀和与其他结构。

## 9. C# 14 实现原则

### 9.1 输入副作用必须明确

原地题方法名和注释明确说明修改输入。其他方法尽量复制输入，例如 56 复制区间、215 Quickselect 复制数组、994 复制网格。这样测试可以验证调用方数据没有被意外改变。

### 9.2 用 long 保护中间结果

面积、路径数、乘积和三数之和可能超出 int。即使题目约束保证最终值可表示，中间表达式仍应先提升到 long，避免 C# unchecked 回绕产生看似合法的错误值。

### 9.3 nullable 节点表达真实状态

链表和树的空节点使用 `ListNode?` / `TreeNode?`。`!` 只在控制流已经证明非空但编译器无法推断时使用，并尽量让相邻代码说明证明条件。

### 9.4 最小接口表达算法需求

- 只枚举：`IEnumerable<T>`。
- 需要 Count 和下标：`IReadOnlyList<T>`。
- 需要原地写入：`IList<T>`。
- 固定外部题目签名：数组或节点模型。

签名本身就是文档：调用方一眼能看出算法是否需要随机访问或是否会修改集合。

### 9.5 集合表达式与明确目标类型

C# 14 的 `[1,2,3]`、`[]` 和 `[.. values]` 减少样板代码。但当重载同时接受数组和 Span 时，测试可能出现歧义，此时使用 `SequenceEqual` 或显式类型，而不是依赖编译器猜测。

## 10. 测试策略

新增 81 道题均有以题号命名的测试方法，例如 `P84_LargestRectangleArea`。这样可以从测试列表直接审计题库是否真的达到 100，而不是只统计源码中的方法数量。

每类测试重点：

- 原地数组：验证有效前缀或完整修改结果。
- 字符串：验证空串、重复字符、嵌套格式和 Unicode 相关契约。
- 链表：验证节点身份、输入恢复和环。
- 树：验证结构而不只验证某个值。
- 图：验证有环、断连、多源传播和输入不变性。
- DP：验证边界初始化与空间压缩方向。

进一步练习差分测试：

- 31 与“生成全部排列后排序”的小规模参考实现比较。
- 33/34 与线性扫描比较。
- 56 与逐点覆盖参考模型比较。
- 148 与 `OrderBy` 比较。
- 84 与枚举所有区间比较。
- 221 与枚举所有正方形比较。

## 12. 验收标准

完成 100 题后，应能够：

- 根据“有序、连续、连通、层次、依赖、最优前缀”等关键词快速缩小算法范围。
- 在写代码前明确循环或递归不变量。
- 解释为什么双指针可以移动某一侧，而不是仅记住模板。
- 解释为什么某些滑动窗口必须要求正数或固定窗口长度。
- 在链表题中安全保存后继、统一处理头节点并识别引用身份。
- 为树递归写出精确返回值含义。
- 区分 DFS、BFS、多源 BFS、拓扑排序、染色和回溯的状态生命周期。
- 为 DP 写出状态、转移、初始化、遍历顺序和空间压缩依据。
- 在 C# 中处理整数溢出、nullable、锯齿数组、集合枚举版本和输入副作用。
- 用题号测试、边界测试和差分测试证明实现，而不是只通过一个样例。

真正掌握 100 题的标志，是遇到第 101 题时能够重新推导，而不是继续寻找相同代码模板。
