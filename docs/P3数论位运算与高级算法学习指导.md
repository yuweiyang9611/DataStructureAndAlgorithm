# P3 数论、位运算与高级算法学习指导

## 1. P3 为什么不继续机械增加题量

原有仓库已经覆盖常见线性结构、树、图、字符串、动态规划和 100 道 LeetCode 题。P3 的目标不是把数字从 100 改成 150，而是补齐三种此前不足的能力：

1. **整数推理能力**：通过数论和位运算学习溢出、模运算、二进制状态与输出规模。
2. **算法族比较能力**：在已有 Floyd、Dinic、后缀数组和普通 DP 旁边加入 Johnson、Hopcroft-Karp、后缀自动机及三类高级 DP。
3. **证据与观察能力**：使用差分测试、覆盖率阈值、结构化 Trace 和 Mermaid，而不是只依赖几个样例。

每个 P3 模块仍遵循同一个学习顺序：先写输入契约，再找不变量，随后推导复杂度，最后用示例、性质或差分测试验证。

## 3. 数论：为什么欧几里得算法有效

实现位置：`DataStructureAndAlgorithm/NumberTheory/NumberTheoryAlgorithms.cs`。

### 3.1 gcd 为什么可以不断取余

设 `a = qb + r`。任何同时整除 `a` 和 `b` 的数也会整除 `r = a - qb`；反过来，同时整除 `b` 和 `r` 的数也会整除 `a`。因此：

```text
gcd(a, b) = gcd(b, a mod b)
```

每次非零余数都严格小于除数，所以算法一定终止。代码使用 `ulong` 返回绝对值，因为 `Math.Abs(long.MinValue)` 无法放进 `long`。先计算 `-(value + 1)` 再加一，可以安全得到 `2^63`。

### 3.2 lcm 为什么先除后乘

数学关系是：

```text
lcm(a, b) = |a| * |b| / gcd(a, b)
```

代码写成 `|a| / gcd * |b|`，结果相同，但中间值更小。最终结果仍可能超过 `ulong`，因此使用 `checked` 明确抛出溢出异常，而不是静默回绕。

### 3.3 扩展欧几里得为什么返回 BigInteger

扩展算法除了 gcd，还维护：

```text
a * x + b * y = gcd(a, b)
```

回代系数可能在中间步骤超出 `long`。P3 返回 `BezoutIdentity`，并用 `BigInteger` 保存 gcd 和系数，使 API 对整个 `long` 输入域都成立。测试不只检查某个预期系数，而是重新计算等式；因为贝祖系数不唯一，验证关系比验证固定答案更正确。

### 3.4 模快速幂为什么是对数复杂度

指数的二进制展开决定哪些平方项要乘入结果。例如 `13 = 8 + 4 + 1`，所以只需要连续平方并选取对应项。每轮把指数右移一位，循环次数是 `O(log exponent)`。

乘法在取模之前可能溢出 `long`，因此教学实现使用 `BigInteger` 保存中间乘积。这里的重点是理解二进制快速幂；生产中的固定宽度高性能实现还可以继续学习无溢出乘法或 Montgomery Reduction。

### 3.5 模逆元为什么必须互质

`value` 的模逆元是满足 `value * inverse ≡ 1 (mod modulus)` 的数。根据贝祖等式，只有 `gcd(value, modulus) = 1` 时，右侧才能组合出 1。代码先运行扩展欧几里得，不互质就抛出 `ArgumentException`，避免返回一个看似正常但数学上不存在的结果。

### 3.6 筛法为什么从 p² 开始

处理质数 `p` 时，`2p、3p ... (p-1)p` 都包含比 `p` 更小的质因子，已经被之前的轮次标记。因而从 `p²` 开始既正确又减少重复工作。循环条件写成 `p <= n / p`，避免计算 `p * p` 时发生整数溢出。

### 3.7 Fibonacci 为什么使用矩阵快速幂

Fibonacci 递推可以表示为固定矩阵的幂。矩阵乘法满足结合律，所以能够使用与标量快速幂相同的二进制拆分。复杂度从线性下降为 `O(log n)`，并用 `BigInteger` 展示第 100 项以后仍然正确的结果。

## 4. 位运算：什么时候位技巧是真正的状态表达

实现位置：`DataStructureAndAlgorithm/BitManipulation/BitAlgorithms.cs`。

### 4.1 `value & (value - 1)` 为什么删除最低置位

减一会把最低的 `1` 变成 `0`，并把它右边的零全部变成一；再与原值按位与，右侧新增的一被清掉，最低置位也被删除。因此置位计数的循环次数等于一的数量。

业务代码通常应使用 `BitOperations.PopCount`，因为运行时可以利用 CPU 指令。仓库同时保留教学实现和框架实现，并用测试做结果对照。

### 4.2 为什么零不是 2 的幂

`value & (value - 1) == 0` 对零也成立，所以必须先判断 `value != 0`。位公式如果缺少定义域，常常会在边界上产生貌似合理的错误。

### 4.3 子掩码枚举为什么使用 `(submask - 1) & mask`

减一把当前子掩码跳到更小的二进制组合，再与原掩码相交会删除所有不属于原集合的位。序列最终到零，且不会重复。

### 4.4 为什么子集枚举限制 30 个元素

算法可以写得很短，但输出数量是 `2^n`。限制不仅防止 `1 << n` 的位移回绕，也提醒学习者：惰性枚举只能推迟成本，不能消除指数级输出。

## 5. Johnson：稀疏图为什么不总用 Floyd

实现位置：`DataStructureAndAlgorithm/Graph/P3GraphAlgorithms.cs`。

Floyd-Warshall 的优势是实现稳定、支持负边且查询方便，但时间固定为 `O(V³)`。Johnson 针对稀疏图：

1. 建立一个到所有顶点权重为零的假想超级源点。
2. 用 Bellman-Ford 求每个顶点的势能 `h(v)`。
3. 把边权改写为 `w'(u,v) = w(u,v) + h(u) - h(v)`。
4. 在非负的新边权上从每个顶点运行 Dijkstra。
5. 用势能还原原始距离。

任意路径的势能项会首尾抵消，所以同一起点终点之间的路径相对大小不变。Bellman-Ford 又保证新边权非负；若仍能松弛，则原图含负环，最短路没有定义。

测试同时运行 Johnson 和 Floyd-Warshall，逐顶点对比较距离。这种差分测试比只检查一条路径更有证据力。

## 6. Hopcroft-Karp：为什么一次寻找多条增广路

普通二分图匹配每找到一条增广路就修改匹配，最坏需要反复扫描大量相同边。Hopcroft-Karp 先用 BFS 建立最短增广路层次，再用 DFS 在同一层次图中找一组互不冲突的增广路。

匹配始终维护两个方向的映射：`left -> right` 与 `right -> left`。任何更新都必须同时修改两边，否则下一轮会把已经匹配的端点再次使用。

## 7. 欧拉路径：为什么答案要逆序构造

Hierholzer 不在第一次走边时立刻把顶点写进最终答案，因为当前选择之后可能还要插入一个环。算法一直走到无边可走，才把当前顶点加入逆序答案；回退过程中，局部环自然插入正确位置。

有向图欧拉路径的度数条件是：

- 起点 `out - in = 1`；
- 终点 `in - out = 1`；
- 其他顶点入度等于出度；
- 或者所有顶点入度等于出度，形成欧拉回路。

度数条件还不够，最终路径长度必须为 `edgeCount + 1`。否则说明存在与起点不连通的边分量。

## 8. 倍增 LCA：为什么预处理祖先的 2 的幂

`BinaryLiftingTree<TVertex>` 保存每个节点的 `2^k` 级祖先。查询时把深度差按二进制拆开，就能在 `O(log n)` 内把较深节点提升到同一深度；随后从最大的幂向下尝试同时提升两个节点，最后它们的父节点就是 LCA。

构造函数要求边数等于顶点数减一，并验证从根能够访问全部顶点。这样后续查询不必每次重新怀疑输入是否真的是树。

## 9. 最大流与最小割为什么要一起学习

实现位置：`DataStructureAndAlgorithm/Graph/P3FlowAlgorithms.cs`。

P3 的追踪版 Dinic 返回：

- 最大流数值；
- 每条原始边的容量与实际流量；
- 最小割的源侧顶点集合。

最大流结束时，残量网络中已经不存在从源到汇的路径。从源点沿正残量边仍可到达的顶点构成集合 `S`，其余顶点构成 `T`。原网络中所有 `S -> T` 边都已经饱和，容量和等于最大流。

测试会从结果中重新计算割容量并与最大流比较，实际验证 max-flow = min-cut，而不是只相信实现返回的数值。

## 10. Manacher：为什么镜像只能提供下界

实现位置：`DataStructureAndAlgorithm/PatternMatching/P3StringAlgorithms.cs`。

Manacher 维护当前最靠右的回文区间。新中心位于该区间内时，它关于区间中心的镜像已经计算过，因此可以复用镜像半径；但复用范围不能超过当前右边界，因为边界以外还没有比较证据。

代码分别计算奇数长度与偶数长度回文，避免在字符串中插入特殊分隔符，也避免分隔符与真实输入字符冲突。

## 11. 后缀自动机：状态为什么能代表多个子串

后缀自动机的一个状态代表一组结束位置集合相同的子串。`MaximumLength` 是其中最长长度，suffix link 指向最长的、结束位置集合更大的真后缀状态。

新状态贡献的不同子串数量为：

```text
state.MaximumLength - link(state).MaximumLength
```

构造时出现转移长度不连续，就复制目标状态形成 clone。clone 继承转移和 suffix link，但缩短最大长度，使自动机仍保持确定性和最小状态结构。

P3 支持：

- 判断模式是否为子串；
- 统计不同子串数量；
- 在线计算与另一个字符串的最长公共子串长度。

## 12. Rune：为什么 char 不等于一个用户可见字符

C# 的 `char` 是 UTF-16 code unit。非 BMP 字符（例如许多 emoji）由一对代理项组成，按 char 滑动可能把一个 Unicode 标量拆开。

`LongestSubstringWithoutRepeatedRunes` 使用 `string.EnumerateRunes()`，按 `Rune` 去重，同时记录 UTF-16 起点和长度。这样结果既按标量值正确计数，也可以安全传给 `Substring`。

需要注意，Rune 仍不等于完整的“用户可见字素簇”；组合音标和 emoji 序列还需要更高层的文本分割规则。

## 13. 三类高级动态规划为什么要分开学习

实现位置：`DataStructureAndAlgorithm/DynamicProgramming/P3DynamicProgrammingAlgorithms.cs`。

### 13.1 区间 DP

矩阵链和 Burst Balloons 都先确定区间边界，再枚举最后一次合并或最后一个决策。关键不是二维数组，而是“选定最后决策后，左右子问题相互独立”。

### 13.2 树形 DP

树上最大权独立集为每个节点维护：

- `Take`：选择当前节点，所有孩子必须 Skip；
- `Skip`：不选当前节点，每个孩子可取 Take/Skip 较大值。

实现使用显式栈建立父子顺序，再逆序计算状态，避免深树递归造成调用栈溢出。

### 13.3 状态压缩 DP

Held-Karp TSP 的状态 `(mask, last)` 表示已访问 `mask` 中的顶点且当前停在 `last`。位掩码让集合成为数组下标，但状态数量仍是 `n * 2^n`，所以 API 明确限制最多 18 个顶点。

状态压缩不是把指数问题变成多项式，而是用可控内存消除重复搜索。

## 15. 结构化 Trace 和 Mermaid 为什么分层

`IAlgorithmTraceSink` 仍是核心算法唯一依赖。算法不知道结果会写入控制台、JSON、日志还是 UI。P3 新增：

- 欧几里得每轮余数追踪；
- 矩阵链每次更优分割追踪；
- Dinic 层次图、增广流和最小割追踪；
- `MermaidTraceRenderer`，把事件序列转成 Markdown 可嵌入的流程图。

运行 JSON：

```powershell
dotnet run --project DataStructureAndAlgorithm.P3Demo -- all json
```

运行 Mermaid：

```powershell
dotnet run --project DataStructureAndAlgorithm.P3Demo -- dinic mermaid
```

事件中的 State 必须是快照。若直接保存调用者的可变 Dictionary，后续修改会篡改历史步骤，演示结果就不再可信。

## 16. CI 质量门禁为什么这样设置

P3 新增以下仓库级配置：

- `Directory.Build.props`：统一 C# 14、nullable、确定性构建和编译器警告策略；
- `Directory.Build.rsp`：固定 `.NET 10` 默认分析模式，避免一次启用全部风格规则产生数百条历史噪声；
- `.editorconfig`：统一字符集、换行、缩进和现代语法建议；
- `.github/workflows/quality.yml`：格式、Release 构建、测试和覆盖率阈值；
- `tools/check_coverage.ps1`：解析 Cobertura 总覆盖率并低于阈值时失败。

阈值设置为行覆盖率 80%、分支覆盖率 70%。P3 完成时实测基线明显高于阈值，保留余量是因为覆盖率只能说明代码是否执行，不能单独证明断言质量。关键结构继续使用 Stryker 变异测试验证“测试能否杀死错误”。

格式门禁使用：

```powershell
dotnet format DataStructureAndAlgorithm.slnx --verify-no-changes --no-restore
```

Windows 本机若禁止 `.ps1`，可只对仓库脚本使用一次性策略，不要修改全局系统策略：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_coverage.ps1 `
  -Report path/to/coverage.cobertura.xml -MinimumLineCoverage 80 -MinimumBranchCoverage 70
```
