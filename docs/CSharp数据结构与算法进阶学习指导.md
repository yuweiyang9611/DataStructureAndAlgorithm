# C# 数据结构与算法进阶学习指导

需要把进阶结构应用到经典题型时，继续阅读 [LeetCode 100 题完整学习指导](LeetCode100题完整学习指导.md)。

## 1. 使用方式

本篇建立在主学习指导的线性结构、排序、树、基础图、动态规划和回溯之上，重点训练三种能力：

1. 把基础结构组合成真实组件，例如“字典 + 双向链表 = LRU”。
2. 根据操作类型和输入约束选择区间结构、图算法或字符串算法。
3. 使用 C# 14 清楚表达泛型约束、比较规则、所有权、异常契约和测试。

每个专题建议按以下顺序学习：

1. 只看 API，写出输入、输出和复杂度预期。
2. 阅读源码注释，手算最小输入下的状态变化。
3. 阅读测试，区分正常、边界、异常和不变量断言。
4. 隐藏实现独立重写，再运行相同测试。
5. 完成章节练习，并解释为什么实现正确。

## 3. 哈希表：从哈希码到平均 O(1)

### 3.1 映射过程

哈希表把任意键映射到数组桶：

```text
key -> comparer.GetHashCode(key) -> 非负整数 -> 对桶数量取模
```

哈希码不是唯一编号。不同键得到相同哈希码，或取模后落入同一个桶，都是正常的哈希冲突。最终必须使用 `IEqualityComparer<TKey>.Equals` 确认键是否相等。

### 3.2 链地址法与负载因子

链地址法让每个桶保存一组 Entry。查找只扫描目标桶。负载因子是：

```text
Count / Capacity
```

负载过高时，单桶平均条目增多。本项目在加入新元素会超过 0.75 前扩容。

### 3.3 为什么扩容必须重新散列

桶下标包含 `% Capacity`。容量改变后，同一个键可能属于另一个桶，因此不能只复制桶数组，必须重新计算每个条目的桶下标。

扩容是 O(n)，但不是每次插入都发生，所以插入的平均摊还复杂度仍为 O(1)。最坏情况下所有键冲突，操作会退化为 O(n)。

### 3.4 比较器必须一致

若使用 `StringComparer.OrdinalIgnoreCase`，`"Algorithm"` 和 `"ALGORITHM"` 是同一个键。哈希码和相等判断必须来自同一个比较器，否则相等键可能落入不同桶。

练习：

- 编写总是返回相同哈希码的比较器，验证冲突处理。
- 记录扩容前后每个键的桶位置。
- 阅读本项目开放寻址实现，手算线性探测和墓碑复用，再与链地址法比较缓存局部性和删除成本。

验收标准：能解释“平均 O(1)”为什么不是“最坏 O(1)”。

## 4. 并查集：动态连通性

并查集支持：

- `Find(x)`：返回 x 所在集合的代表。
- `Union(a, b)`：合并两个集合。
- `AreConnected(a, b)`：判断是否连通。

### 4.1 路径压缩

Find 找到根以后，把路径上的节点直接指向根：

```text
压缩前：1 -> 2 -> 3 -> 4
压缩后：1 -> 4，2 -> 4，3 -> 4
```

第一次查询承担压缩成本，后续查询变快。

### 4.2 按大小合并

合并时让较小树挂到较大树的根下，限制树高。路径压缩和按大小合并共同使用时，摊还复杂度是 O(α(n))，现实规模下非常接近 O(1)。

典型用途：Kruskal、无向图连通分量、账户合并、等价关系分组。

练习：

- 为每个集合维护最小元素或权重和。
- 使用并查集计算二维网格岛屿数量。
- 验证 `SetCount` 每次有效 Union 恰好减少 1。

## 5. Trie：以前缀作为路径

插入 `car` 和 `card` 后，`car` 节点既是完整单词，又是 `card` 的前缀。因此必须使用 `IsWord` 区分“单词结束”和“仍有孩子”。

删除 `car` 时不能删除仍被 `card` 使用的节点。递归返回时，只有节点同时满足以下条件才可以清理：

- 它不代表完整单词。
- 它没有任何孩子。

自动补全先定位前缀节点，再 DFS 收集单词。需要字典序结果时，按字符顺序访问孩子。

### Unicode 注意事项

C# 的 `char` 是 UTF-16 code unit，一个视觉字符可能包含两个代理项或多个组合字符。国际化搜索需要考虑：

- 使用 `System.Text.Rune` 按 Unicode 标量值遍历。
- 大小写折叠与文化规则。
- Unicode Normalization。
- Ordinal 比较还是文化相关比较。

练习：增加前缀计数、删除数量和最大返回数量；再实现基于 Rune 的版本。

## 6. LRU：组合数据结构

只用字典可以 O(1) 查找，但不知道最久未使用项；只用链表可以 O(1) 移动和淘汰，但按键查找是 O(n)。组合后：

```text
Dictionary<TKey, LinkedListNode<Entry>> -> O(1) 定位
LinkedList<Entry>                       -> O(1) 移动与淘汰
```

必须维护：

- 字典中的每个节点都在链表中。
- 链表中的每个条目能在字典找到同一个节点。
- 链表头是最近使用，尾部是最久未使用。
- 更新已有键不会增加 Count。
- 淘汰时同时删除字典和链表记录。

教学实现不是线程安全的。生产缓存还要考虑并发、过期时间、缓存击穿、异步工厂、取消和 `IDisposable` 值的释放。

练习：用一个简单但较慢的参考模型生成随机操作序列，与 LRU 做状态机差分测试。

## 7. Fenwick 树与线段树

### 7.1 如何选择

| 需求 | 前缀和数组 | Fenwick 树 | 线段树 |
| --- | --- | --- | --- |
| 静态区间和 | 查询 O(1) | 查询 O(log n) | 查询 O(log n) |
| 单点更新 | O(n) | O(log n) | O(log n) |
| 区间最小/最大 | 不直接支持 | 不适合 | O(log n) |
| 通用结合操作 | 否 | 有限 | 是 |
| 实现复杂度 | 低 | 中 | 较高 |

数据不更新时，普通前缀和通常最好。高级结构不是默认答案。

### 7.2 Fenwick 的 lowbit

内部使用 1 基下标，`i & -i` 得到最低有效位，决定节点覆盖的区间长度：

```text
i = 12 = 1100₂
lowbit = 0100₂ = 4
```

更新用 `i += lowbit(i)` 移向包含当前位置的更大区间；查询用 `i -= lowbit(i)` 拆解前缀。

### 7.3 线段树的结合律

通用 combine 必须满足：

```text
combine(combine(a, b), c) == combine(a, combine(b, c))
```

加法、最小值、最大值和字符串连接满足结合律；减法不满足。交换律不是必须的，本项目分别维护左右累积结果，所以字符串连接仍保持顺序。

### 7.4 半开区间

区间 API 使用 `[start, endExclusive)`：长度是 `endExclusive - start`，空区间是 `[x, x)`，相邻区间不会重叠，并与 Span/Range 的切片思维一致。

练习：

- 用直接循环作为参考模型，随机验证更新和查询。
- 在线段树上实现区间最小值。
- 阅读现有 `LazyRangeSumSegmentTree`，手算懒标记下推；再扩展为区间赋值或区间最小值，解释多个标记如何组合。

## 8. 图算法选择

最短路最小化某个源点到目标点的路径长度；最小生成树最小化连接全部顶点所选边的总权重。两者不是同一个问题。

| 算法 | 图要求 | 结果 | 复杂度 |
| --- | --- | --- | --- |
| BFS | 无权或等权 | 单源最短边数 | O(V + E) |
| Dijkstra | 非负权 | 单源最短路 | O((V + E) log V) |
| Bellman-Ford | 可有负权 | 单源最短路、负环检测 | O(VE) |
| Floyd-Warshall | 可有负权、无负环 | 所有点对最短路 | O(V³) |
| Kruskal | 无向图 | 最小生成森林 | O(E log E) |
| 拓扑排序 | 有向无环图 | 依赖顺序 | O(V + E) |

### 8.1 Bellman-Ford

第 k 轮松弛后，得到最多使用 k 条边的最短路径。简单路径最多使用 V-1 条边，因此执行 V-1 轮足够。

若之后仍能缩短，说明存在从源点可达的负权环。沿负环反复行走会让路径无限下降，所以最短路径不存在。

### 8.2 Kruskal

按权重从小到大检查边：

1. 两端属于不同连通分量，加入并 Union。
2. 两端已经连通，加入会形成环，跳过。

图不连通时不存在单棵生成树，本项目明确返回最小生成森林和 `ComponentCount`。

练习：阅读现有 Prim 与 Floyd-Warshall；用随机连通图把 Prim 和 Kruskal 做差分，再让 Bellman-Ford 返回一条实际负环。

## 9. 进阶动态规划

### 9.1 编辑距离

状态：

```text
dp[i, j] = source 前 i 个字符变成 target 前 j 个字符的最少操作数
```

转移包括：

- 删除：`dp[i - 1, j] + 1`
- 插入：`dp[i, j - 1] + 1`
- 替换或保持：`dp[i - 1, j - 1] + cost`

当前行只依赖上一行和当前行左侧，所以可以压缩到 O(min(n,m)) 空间。代价是无法直接恢复具体编辑步骤。

### 9.2 最长递增子序列

O(n²) DP 易于理解。进阶版本维护每个长度对应的最小结尾，并通过二分查找降到 O(n log n)。

最小结尾数组不一定就是实际 LIS。恢复结果需要保存每个长度当前结尾的原始下标，以及每个元素的前驱下标。

动态规划自检：

- 状态是否足以描述未来决策？
- 转移是否覆盖所有选择？
- 初始化是否正确描述空输入？
- 填表方向是否保证依赖已计算？
- 一维压缩是否错误复用了本轮状态？
- 只返回最优值，还是需要恢复具体方案？

## 10. 字符串算法进阶

| 算法 | 核心思想 | 适用场景 |
| --- | --- | --- |
| 朴素匹配 | 每个起点逐字符比较 | 小输入、教学基线 |
| KMP | 利用模式串前后缀避免文本回退 | 单模式精确匹配 |
| Rabin-Karp | 滚动哈希比较窗口 | 多模式、重复窗口、二维扩展 |
| Z Algorithm | 计算每个位置与整串前缀的最长匹配 | 前缀匹配、周期、模式拼接 |

Rabin-Karp 中哈希相等只表示“可能匹配”。不同字符串可能哈希冲突，必须继续比较原字符：

```csharp
text.AsSpan(start, pattern.Length).SequenceEqual(pattern.AsSpan())
```

Z Algorithm 维护最靠右的前缀匹配区间 `[left, right)`。新位置在区间内时可以复用已有 Z 值，再从右边界继续比较。

练习：使用 `pattern + separator + text` 和 Z 数组寻找全部匹配，并说明分隔符必须满足什么条件。

## 11. 数组、贪心和非比较排序

### 11.1 Two Sum

字典保存已经出现的值到下标。当前值 x 查找 `target - x`。先查再加入，保证不会重复使用同一个位置。

### 11.2 单调队列

滑动窗口最大值保存下标，并保证对应值单调递减：

- 队头过期就移除。
- 新值不小于队尾值时，旧队尾不可能再成为未来最大值。
- 队头始终是当前窗口最大值。

必须保存下标而不是只保存值，才能判断过期并处理重复值。

### 11.3 Kadane

若当前累计和为负，它只会拖累后续区间，应从当前位置重新开始。不能把最佳值初始化为 0，否则全负数组会错误返回空区间。

### 11.4 区间调度

每次选择结束最早的可行区间。正确性可以用交换论证：任意最优解的第一个区间都可以替换为结束更早的贪心选择，而不会减少后续选择数量。

贪心不是“选择看起来最好”，必须证明局部选择能扩展为全局最优。

### 11.5 计数排序

复杂度是 O(n + k)，k 是值域宽度。两个整数若分别接近 `int.MinValue` 和 `int.MaxValue`，计数数组仍会巨大。因此 API 必须检查值域，而不能只看元素数量。

## 12. 组合搜索

括号生成的状态是已放左、右括号数量：

- 左括号未达到 pairCount 时可以添加。
- 只有 `closeCount < openCount` 时才能添加右括号。

构造中剪枝比生成全部字符串后过滤更高效。

子集问题中，每个位置有“不选”和“选”两条分支，n 个元素产生 2ⁿ 个子集。输出本身就是指数规模，无法通过算法技巧消除。

练习：实现去重排列、组合总和、数独和单词搜索；每次递归返回前检查状态是否完全恢复。

## 13. 更深入的 C# 14 实践

### 13.1 API 与所有权

- `IEnumerable<T>`：只承诺可枚举，可能延迟执行或只能枚举一次。
- `IReadOnlyList<T>`：支持 Count 和随机访问。
- `IList<T>`：允许原地修改。
- `ReadOnlySpan<T>`：同步调用期间的连续内存视图，不拥有内存。
- 数组副本：调用方获得独立快照。

签名应使用满足算法需求的最小接口。排序需要写入，使用 `IList<T>`；LIS 需要随机访问，使用 `IReadOnlyList<T>`。

### 13.2 现代语法的适用边界

```csharp
int[] values = [1, 2, 3];
List<int> list = [1, 2, 3];
return [];
return [.. source, newValue];
```

集合表达式依赖清晰的目标类型。若重载同时接受数组和 Span，可能需要明确类型来消除歧义。

主构造函数适合初始化关系简单的小型节点。初始化包含大量验证、条件或资源管理时，普通构造函数更清晰。

`record struct` 适合小型不可变值，例如 Interval 和边；具有身份、可变链接或较大字段的节点适合 class。

### 13.3 溢出与容量增长

容量翻倍使用 `checked` 可以把整数溢出转为明确异常：

```csharp
var newCapacity = checked(oldCapacity * 2);
```

涉及中点使用 `left + (right - left) / 2`。涉及值域宽度时先转 `long`，避免 `maximum - minimum` 在 int 中溢出。

### 13.4 惰性枚举与快照

`yield return` 是惰性的，方法调用时不立即遍历。底层集合在枚举期间变化，结果可能改变或抛异常。

LRU 键顺序返回快照，因为它表达某一时刻的状态；哈希表枚举器是惰性的，更接近 BCL 集合行为。

### 13.5 线程安全

本项目的数据结构默认都不是线程安全的。简单给每个方法加锁也不一定让复合操作原子化。学习并发结构前应掌握锁粒度、内存可见性、`Interlocked`、不可变快照和 `ConcurrentDictionary` 的工厂语义。

## 14. 测试进阶方法

### 14.1 差分测试

对相同随机输入运行教学实现和参考实现：

- 排序与 `OrderBy` 比较。
- 哈希表与 `Dictionary` 比较。
- LRU 与简单列表模型比较。
- Fenwick/线段树与直接循环比较。
- Kruskal 与 Prim 的总权重比较。

随机种子必须固定，失败时输出种子和操作序列。

### 14.2 状态机测试

生成 Add、Remove、Update、Query、Clear 等命令，每执行一步就与参考模型比较 Count、内容和查询结果。这类测试比只调用一次 API 更容易发现状态损坏。

### 14.3 不变量验证

- 哈希表：每个 Entry 的桶下标正确，Count 等于条目总数。
- 并查集：沿 Parent 最终到达自指根，不存在其他父指针环。
- LRU：字典数等于链表数，键无重复。
- 线段树：父节点等于两个孩子的 combine。
- 最小生成森林：边数等于 `V - ComponentCount` 且不成环。

### 14.4 性能测试

BenchmarkDotNet 基准应使用多个输入规模，分开测量构建与查询，避免把随机数据生成算入目标方法，消费返回值，并同时观察分配量和耗时。

## 17. 四个正确性修复：为什么原实现会出错

### 17.1 Huffman 编码为什么不能返回整数

旧 API 返回 `uint`。这不是单纯的容量问题，而是表示模型错误：Huffman 码是“带长度的位序列”，整数只保存数值。

```text
位串 0、00、000 -> 整数都等于 0
位串 00101      -> 整数等于 5，长度和两个前导零丢失
```

因此 `CalculateHuffmanCode` 现在返回 `Dictionary<T, string>`。字符串直接表达位和长度，编码深度也不再受 32 位限制。实现仍从叶子沿 `Parent` 回溯：当前节点是父节点左孩子就记录 `0`，是右孩子就记录 `1`。回溯方向与最终编码相反，所以先收集位、最后反转。这里没有在循环头部插入字符，因为 `StringBuilder.Insert(0, ...)` 会反复移动已有内容，可能把线性过程退化为平方级。

建树使用 `PriorityQueue<Node, (Weight, Order)>`。`Weight` 保证每次取出两棵最轻的树，`Order` 只在权重相同的时候提供稳定顺序。相同权重可能产生多棵形状不同但带权路径长度相同的最优树，所以测试不再绑定某一种左右形状，而是检查：

- 根权重等于全部叶权重之和。
- 每个编码非空且只包含 `0/1`。
- 任意编码都不是另一编码的前缀。
- `Decode(Encode(source))` 恢复原序列。

这种测试验证的是算法契约，不是优先队列碰巧采用的平局顺序。

### 17.2 AVL 的 Change 为什么必须先验证

直接修改节点值可能破坏 BST 顺序，所以 Change 仍应由“删除旧值 + 插入新值”组成。旧实现的问题是操作顺序：如果先删除旧值，而新值已经存在，随后 Insert 抛异常，树就只完成了一半操作。

现在的顺序是：

1. 确认旧值存在，否则立即失败。
2. 若比较器认为新旧值相等，直接返回。
3. 确认新值不存在，否则立即失败。
4. 前置条件全部满足后才执行 Delete 和 Insert。

这称为先验证、后变更。它不等于数据库事务，但在当前单线程、内存内且 Insert 不会发生其他可恢复失败的契约下，可以保证常见失败不会留下半完成状态。测试在异常后同时检查旧值、新值和树内容，避免只断言“确实抛了异常”。

### 17.3 树重建为什么要区分空树和非法序列

空的前序与空的中序确实表示空树；长度不同的两条序列不是空树，而是调用错误。把两者都返回 null 会掩盖数据损坏。公共验证器现在依次检查：

- 两条序列长度相同。
- 每条序列内部没有重复节点。
- 两条序列包含相同节点集合。
- 构造过程中每个根在当前中序区间内。

唯一性要求很重要。若值重复，仅凭“前序 + 中序”或“后序 + 中序”通常不能唯一确定树，字典也会覆盖重复键的位置。递归解法用中序位置字典把查根从 O(n) 降为 O(1)，总时间从可能的 O(n²) 降为 O(n)。迭代解法使用显式栈模拟回溯，并在结束时确认整条中序序列被完全消费，借此拒绝“长度和集合正确但左右分区矛盾”的输入。

泛型约束也从 `IComparable<T>` 收紧为 `notnull`。算法只需要相等性，不比较大小；不应要求调用方实现没有被使用的能力。

### 17.4 线索化后为什么还要记录遍历类型

同一空指针在前序线索中可能指向 A，在中序线索中可能指向 B。若结构不记录当前是哪一种线索，遍历方法无法安全地解释指针。`CurrentThreadingOrder` 现在显式保存该状态；重新线索化会先只沿 `Tag == 0` 的真实孩子收集节点、清除旧线索，再按新顺序建立前驱和后继。

三种无栈遍历分别利用不同规则：

- 前序：有真实左孩子就向左，否则右指针无论是右孩子还是后继线索都可直接跟随。
- 中序：先到最左节点；右指针是线索就直接到后继，否则进入右子树的最左节点。
- 后序：先下降到最先访问的叶子；后继线索可直接跟随，没有线索时借 `Parent` 判断应进入父节点右子树还是回到父节点。

后序比前两种更难，是因为访问完孩子后必须知道父节点。为节点增加 Parent 将这部分信息显式化，使匹配当前线索类型的前、中、后序遍历都只需 O(1) 额外空间。层序遍历仍需要队列保存同层候选，空间为 O(w)；不能为了宣传“线索树无栈”而隐藏这一事实。

## 18. 双向链表与数组双端队列

### 18.1 双向链表为什么多保存 Previous

单向链表即使维护 Tail，删除尾节点仍要从 Head 找到倒数第二个节点，因此是 O(n)。双向链表让尾节点直接知道前驱，`RemoveLast` 变成 O(1)，代价是每个节点多一个引用，插入删除时也必须同时维护两个方向。

删除中间节点的核心连接为：

```text
current.Previous.Next = current.Next
current.Next.Previous = current.Previous
```

头尾是特殊边界，所以实现把它们分别复用到 `RemoveFirst` 和 `RemoveLast`，避免在多个位置重复修改 Count 与头尾指针。删除后主动断开节点引用不是 GC 的必要条件，但能让调试器中的“节点已经离表”更清楚。

### 18.2 双端队列为什么使用循环数组

普通数组若每次在下标 0 插入都搬移全部元素，头部操作是 O(n)。循环数组只移动 `_head`：逻辑下标 i 的物理位置是

```text
(_head + i) % Capacity
```

数组尾部不够不代表没有空间，空槽可能位于数组开头，这就是“绕回”。只有 Count 等于 Capacity 时才扩容。扩容必须按逻辑顺序复制到新数组的 `[0, Count)`，再令 `_head = 0`；直接复制物理数组会把绕回后的两段顺序颠倒。

数组双端队列拥有更好的缓存局部性，链式双端队列则无需整体扩容。选择取决于是否重视连续内存、容量波动和节点引用稳定性。

## 19. 开放寻址哈希表：Empty、Occupied、Deleted 三态

线性探测从初始桶开始依次检查后续槽位，并在数组末尾取模绕回。槽位不能只有“有值/无值”两态。假设 A、B、C 冲突后连续排列，删除 B 若直接设为 Empty，查找 C 会在 B 的位置误以为探测链结束。

因此槽位状态为：

- Empty：从未使用，查找可以终止。
- Occupied：比较键，相等则命中，不等继续。
- Deleted：旧条目的墓碑；查找必须继续，插入可以优先复用。

实现同时维护 Count 和 `_usedSlots`。Count 只统计真实条目；usedSlots 还包括墓碑。若只根据 Count 判断负载，大量删除会让探测链越来越长却永不整理。usedSlots 超过 0.70 时：真实条目也多就扩容；主要是墓碑多就使用相同容量重散列，以较低成本清理墓碑。

索引使用 `(uint)hashCode % capacity`，而不是 `Math.Abs(hashCode)`。`Math.Abs(int.MinValue)` 仍会溢出，转成 uint 则能无分支地得到合法非负余数。

## 20. 桶排序与基数排序

### 20.1 桶排序为什么不是“永远 O(n)”

桶排序先根据 `(value - min) / (max - min)` 把值归一化到 `[0, 1]`，再映射到桶。最大值会得到 1，乘桶数后恰好越过末尾，所以实现用 `Min(index, bucketCount - 1)` 压回最后一桶。

数据均匀时，每桶很小，整体接近 O(n + k)；数据集中时，全部元素可能落入同一桶，复杂度退化为桶内 `List.Sort` 的 O(n log n)。API 拒绝 NaN、正负无穷和溢出的极端跨度，因为这些值无法形成可靠的线性区间映射。默认桶数取 sqrt(n)，只是通用折中，不是所有数据分布的最优参数。

### 20.2 LSD 基数排序为什么要求稳定

LSD 从最低有效位开始。高位分配时，必须保留低位已经建立的相对顺序，否则前一轮结果会被破坏。本实现每轮按 source 原顺序写入目标数组，通过前缀位置保证稳定。

每轮处理 8 位，共 256 个桶，32 位整数固定执行四轮。`value ^ int.MinValue` 只翻转最高符号位：所有负数被映射到 uint 的低半区，非负数映射到高半区，且各自内部顺序不变。因此无需把正负数拆开，也不会对 int.MinValue 取绝对值发生溢出。

## 21. 左倾红黑树：用局部规则维护全局高度界

左倾红黑树把红链接解释为 2-3 树中同一个多键节点的内部连接。四条不变量是：

1. 根节点是黑色。
2. 红节点不能有红孩子。
3. 红链接只向左倾斜。
4. 从任一节点到所有 null 叶子的黑节点数量相同。

插入后的三个局部修复按顺序执行：右红左黑时左旋；连续两个左红时右旋；左右都红时颜色翻转。这些操作不改变中序顺序，旋转负责改变结构，颜色负责保存等价的 2-3 树含义。

删除采用顶向下策略：下降到下一层前，确保将要进入的孩子不是无法直接删除的 2-节点；`MoveRedLeft/Right` 通过颜色翻转和旋转从兄弟方向借一个红链接。删除后 `Balance` 恢复左倾形态。

`HasValidInvariants` 不是业务 API 的必需品，却是学习项目的重要组成：它同时验证严格 BST 区间、红色约束、左倾约束、左右黑高和实际节点数。随机测试每次变更后都调用它，比只看最终排序结果更容易定位第一次破坏结构的操作。

## 22. 跳表：用概率换取简单的平衡逻辑

跳表第 0 层包含所有值；节点若出现在第 k 层，也必然出现在 0 到 k-1 层。查找从当前最高层开始，能向右且不会越过目标就移动，否则下降一层。这个过程与在高速公路和辅路之间切换类似。

新节点从 1 层开始，每次以概率 p 晋升，直到失败或达到 maximumLevel。p=0.5 时高度至少为 k 的概率约为 `1/2^(k-1)`，所以高层节点指数减少，期望搜索路径为 O(log n)。最坏情况下所有节点都只有一层，仍会退化到 O(n)，这与红黑树确定性的最坏 O(log n) 不同。

插入和删除都维护 `update[]`：它记录目标在每一层的直接前驱。插入用它一次性接入新节点的所有层，删除用它绕过目标。固定 `randomSeed` 不是算法要求，而是测试最佳实践：让层高选择可复现，失败不会成为难以重现的偶发现象。

## 23. CI 与测试为什么这样组织

`.github/workflows/ci.yml` 在 master/main 的 push 与 pull request 上运行：

1. Checkout 仓库。
2. 安装 .NET 10 SDK。
3. Restore，单独暴露依赖问题。
4. Release Build，并使用 `--no-restore` 避免重复恢复。
5. Test，并使用 `--no-build` 确保测试的是刚刚构建的产物，同时收集 TRX 与 XPlat Coverage。
6. ReportGenerator 把 Cobertura 数据转换为可读 HTML 和 GitHub Step Summary。
7. `upload-artifact` 即使测试失败也保留 TRX 与覆盖率文件，便于离线定位。

工作流只授予 `contents: read`，因为构建测试不需要写仓库或发布包。`timeout-minutes` 防止异常挂起无限占用 runner。

本轮测试采用四种层次：

- 示例测试：固定小输入，便于手算。
- 边界测试：空结构、单元素、重复值、完整 int 值域。
- 异常测试：非法权重、无效遍历序列、NaN、空结构删除。
- 不变量/差分测试：红黑树逐步验证，跳表与 SortedSet 比较，哈希表强制冲突。
- 性质测试：FsCheck 自动生成并缩减输入，验证排序与红黑树对任意样本都满足规则。
- 状态机测试：每一步都与 Dictionary、LinkedList、SortedSet 对照，而不只比较最终结果。

`.github/workflows/mutation.yml` 不放进每个 PR 的快速门禁，而是每周或手动运行。原因是 Stryker 会反复修改源码并重跑测试，成本远高于普通测试。当前以 Basic 级别和 4 路并发限定 B+ 树、懒标记区间树、BK-tree、Bloom Filter、LFU 与最小费用流六个新增关键文件；如果存活变异过多，应先补能杀死这些变异的测试，而不是直接扩大范围。2026-07-18 的本地完整运行测试 334 个有效变异，分数为 `81.07%`，高于 `60%` break 阈值。

新增算法时不要只提高“测试数量”。更重要的是让每个测试说明一个可能被破坏的契约，并保证失败信息能指出是哪条规则失效。

## 25. 可选算法追踪与 Demo 为什么这样设计

源码入口是 `Diagnostics/AlgorithmTracing.cs`，演示入口是 `DataStructureAndAlgorithm.Demo/Program.cs`。追踪能力没有直接使用 `Console.WriteLine`，因为输出到控制台会把算法与运行环境绑定，单元测试、GUI、Web API 和日志系统都难以复用。当前设计只依赖一个最小接口：

```csharp
public interface IAlgorithmTraceSink
{
    void Record(
        string algorithm,
        string operation,
        string description,
        IReadOnlyDictionary<string, string>? state = null);
}
```

### 25.1 为什么参数可空

Dijkstra、基数排序和 Huffman 把 `IAlgorithmTraceSink? trace = null` 放在末尾，红黑树在构造时可选注入。这样做有三个目的：

- 旧调用代码无需修改，属于向后兼容的附加能力。
- 普通执行只进行一次空值判断，不创建事件列表和状态快照。
- 需要教学动画或 JSON 时，同一算法实现可以注入不同 sink，不复制算法。

红黑树把 sink 放在构造函数，是因为旋转和颜色翻转发生在多个私有递归方法中；把依赖保存为只读字段比层层传参更清楚。Dijkstra 和排序是单次静态调用，参数传入更符合生命周期。

### 25.2 为什么事件是结构化数据

`AlgorithmTraceEvent` 同时保存递增 Step、Algorithm、Operation、Description 和 State。Description 回答“为什么做”，State 保存本步关键值。若只保存一句拼接后的文本，UI 就无法可靠筛选 Relax、RotateLeft 或 Merge，也难以把节点和距离做成动画。

Demo 只做四件事：构造小输入、注入 `CollectingAlgorithmTraceSink`、调用公开 API、把最终结果和事件序列化为 JSON。算法库不知道 JSON 的存在，这保持了依赖方向：展示层依赖算法层，算法层不依赖展示层。

### 25.3 阅读练习

1. 运行 `dotnet run --project DataStructureAndAlgorithm.Demo -- radix`，解释四次 Pass 为什么稳定。
2. 运行 `-- dijkstra`，找出某个顶点被松弛两次的原因。
3. 运行 `-- red-black`，逐步画出 Rotate 与 FlipColors 前后的 2-3 树等价形态。
4. 自己实现一个 Mermaid sink，但不要修改任何算法签名。

性质测试中的排序断言使用标准库结果作为 oracle；红黑树性质同时检查有序去重结果、Count 和所有内部不变量。FsCheck 失败后会“缩减”随机数组，例如把数百项反例缩成几个关键值，这比只报告随机种子更容易理解。

状态机测试固定随机种子，并在每一步比较。开放寻址哈希表会经历覆盖、墓碑、重散列；双端队列会经历两端操作、绕回和扩容；有序集合会经历重复插入和不存在删除。若只比较第 2000 步的最终内容，第一次损坏状态的位置会被隐藏。

## 27. 索引优先队列：为什么需要键到下标的反向索引

普通二叉堆能 O(log n) 入队和出队，但不知道某个 key 当前位于数组哪个位置。要实现 decrease-key，如果线性查找 key，单次更新会退化为 O(n)。`IndexedPriorityQueue<TKey, TPriority>` 同时维护：

- `_heap[index]`：按完全二叉树排列的 key 与 priority。
- `_indexes[key]`：同一个 key 在 `_heap` 中的下标。

每次 Swap 必须同时更新两个 key 的字典下标；出队时先删除根 key，再把末尾元素移到根并下沉。`HasValidInvariants` 同时验证堆序、数量和双向映射，因此能发现“堆看起来有序但字典仍指向旧下标”的隐蔽错误。

API 叫 `EnqueueOrDecrease` 而不是含糊的 Update：已存在 key 只有新优先级更小时才改变。Prim 与 A* 需要的正是这一单向语义；拒绝无意义的 increase 可以减少调用方误用，也让修复方向只有 SiftUp。

## 28. 六个图算法应该怎样选择

### 28.1 Prim 与 Kruskal

两者都求无向图最小生成森林，但观察角度不同：

- Kruskal 按全局边权排序，用并查集拒绝成环边，成本主要是 `O(E log E)`。
- Prim 从一个分量向外扩张，为每个未访问顶点维护当前最轻连接边，索引堆版本为 `O((V+E) log V)`。

实现外层遍历每个未访问起点，所以断开图返回森林并准确增加 `ComponentCount`。Prim 可以接受负边，因为生成树只比较边权，不进行“距离一旦确定就不再变”的最短路推理。

测试让 Prim 与已经验证的 Kruskal 比较总权重。这种算法间差分比绑定某一组边更稳健，因为同权图可能有多棵都正确的最小生成树。

### 28.2 Floyd-Warshall

`distances[i,j]` 表示当前允许的中转点集合下 i 到 j 的最短距离。加入 k 后只有两种可能：不用 k，或走 `i -> k -> j`。三重循环正是这个状态转移。

代码先跳过 `i -> k` 为正无穷的情况，既少做无意义计算，也避免把“不可达 + 负数”误读成有效路径。`next[i,j]` 保存第一跳而不是完整路径，每次改进时继承 `next[i,k]`，所以空间仍为 O(V²)。全部中转完成后若 `distances[v,v] < 0`，说明存在能不断降低代价的负环，最短距离没有定义，必须抛异常。

### 28.3 Tarjan 强连通分量

`discovery[v]` 是首次访问时间，`low[v]` 是 v 的 DFS 子树通过树边和仍在当前栈中的返祖边能够到达的最早时间。只有 `low[v] == discovery[v]` 时，v 才是一个强连通分量的根，可以弹栈直到 v。

关键细节是 `onStack`：指向已经完成的另一个分量的边不能降低 low 值。省略它会把本应分开的分量错误合并。整个过程每个顶点入栈出栈一次，每条边检查一次，因此为 O(V+E)。

### 28.4 桥与割点

无向图同样使用 discovery/low，但判定不同：

- `low[child] > discovery[parent]`：child 子树没有替代路线回到 parent 或更早祖先，所以 parent-child 是桥。
- 非根节点存在 `low[child] >= discovery[parent]`：删除 parent 会让 child 子树断开，所以 parent 是割点。
- DFS 根只有至少两个独立子树时才是割点。

无向边在邻接表中出现两个方向，递归时必须跳过父边，否则会立即把它当返祖边，导致所有桥消失。

### 28.5 A*

A* 的队列优先级是 `f(n) = g(n) + h(n)`：g 是已经支付的真实代价，h 是对剩余代价的估计。h 恒为 0 时就是 Dijkstra；h 越接近真实剩余距离，通常探索越少。

当前 API 强制 h 有限且非负，边权也必须非负。要保证结果最优，还需要调用方提供不高估真实距离的可采纳启发函数；这无法由通用代码自动证明，所以必须写进契约。代码仍保存 g 到 `Distances`，不能把 f 当真实距离返回。

### 28.6 Dinic 最大流

容量网络添加每条正向边时，同时添加容量为 0 的反向残量边，并保存 `ReverseIndex`。发送 x 单位流后，正向残量减 x，反向残量加 x，这使后续搜索能够撤销早先并不理想的选择。

Dinic 每轮先 BFS 构造只向下一层前进的分层图，再用 DFS 发送阻塞流。`nextEdge` 记录每个顶点已经证明无用的边，避免同一轮重复扫描。算法在 `FlowNetwork.Clone()` 上修改残量容量，所以连续两次求流得到相同结果，调用方的原始网络仍可复用。容量网络拒绝自环：自环不会增加 s-t 流量，却会让正向/反向残量索引产生无意义的特殊分支。

## 29. 有序集合统一契约与比较器最佳实践

`IOrderedSet<T>` 只抽取红黑树与跳表真正共享的能力：Count、Add、Remove、Contains、Clear、有序枚举、Comparer 和不变量验证。没有把 Height、CurrentLevel、Rotate 等实现细节硬塞进接口，因为统一接口的目标是允许替换，不是抹平结构差异。

与 `SortedSet<T>` 一样，`Comparer.Compare(x, y) == 0` 同时表示排序相等和集合重复。若使用 `StringComparer.OrdinalIgnoreCase`，加入 `"Alpha"` 后再加入 `"ALPHA"` 必须返回 false。不能一边用 comparer 排序，一边用 `EqualityComparer<T>.Default` 去重，否则集合会出现两个按顺序“相同”的元素，查找边界也不再唯一。

遗留 BST/AVL 仍保留 `IComparable<T>` 约束，避免一次学习扩展引入破坏性 API 变更。新代码优先使用构造函数注入 `IComparer<T>`；若未来迁移旧树，应先提供兼容重载、契约测试和迁移说明。

## 30. Aho-Corasick：失败指针为什么能一次扫描多个模式

Trie 共享所有模式的前缀，但普通 Trie 在某条路径失配后不知道文本中已经读过的后缀还能匹配什么。AC 自动机为每个节点增加 Failure：它指向“当前字符串的最长真后缀，同时也是 Trie 前缀”的节点。

构建失败指针使用 BFS，因为父节点的 Failure 必须先完成，子节点才能沿父 Failure 继续寻找。节点还继承 Failure 节点的 Outputs：例如扫描到 `she` 时，既命中 `she`，也应命中它的后缀模式 `he`。

查找时文本下标永不回退。失配只沿 Failure 跳转，所有跳转的摊还成本与文本长度同阶，因此总成本是 O(文本长度 + 命中数量)。构造函数去除重复模式，明确拒绝空模式；空模式会在每个边界命中，不适合这个返回全部命中的教学 API。

## 31. 后缀数组与 LCP：为什么采用排名倍增

后缀数组保存所有非空后缀起点按字典序排列的顺序。直接比较两个后缀可能逐字符扫描 O(n)，对 n 个后缀排序会很慢。倍增法第 k 轮已知长度 width 片段的排名，只需比较两个整数对：

```text
(rank[start], rank[start + width])
```

这等价于比较长度 `2 * width` 的前缀。每轮 width 翻倍，直到所有排名唯一。当前教学实现使用 `Array.Sort` 比较整数对，易读复杂度 O(n log² n)；继续优化可用计数/基数排序把每轮降到 O(n)，总体 O(n log n)。

LCP 使用 Kasai：按原起点顺序访问后缀，若当前后缀与前一个字典序后缀有 common 个相同字符，那么下一个起点至少还能复用 common-1 个。每个字符最多被增加和减少常数次，因此 LCP 构建 O(n)。

`FindAll` 对排序后的后缀做两次二分，找到以非空 pattern 开头的连续区间。结果对象用只读包装器保护内部后缀数组，调用方不能破坏下一次二分所依赖的排序不变量。返回顺序是后缀字典序，不是文本位置顺序；如果业务需要从左到右展示，应由调用方对结果再排序。

## 32. Sparse Table 与懒标记线段树的选择边界

### 32.1 Sparse Table

第 k 层保存每个起点长度 `2^k` 的聚合值。查询长度 L 时取 `k=floor(log2 L)`，用左端和右端两个长度 `2^k` 的块覆盖区间。两个块可能重叠，所以 combine 除了结合律还必须满足幂等律 `f(x,x)=x`。

Min、Max、GCD 可以使用；Sum 不可以，因为重叠部分会被计算两次。稀疏表预处理 O(n log n)、查询 O(1)，但不支持更新，适合数组固定且查询很多的场景。

### 32.2 懒标记线段树

`LazyRangeSumSegmentTree` 的 `_sums[node]` 始终是节点完整区间的真实和；`_lazy[node]` 表示这个增量已经作用于当前 sum，但尚未传播到孩子。完全覆盖时用 `delta * length` 更新 sum 并累积 lazy，不访问叶子；部分覆盖前调用 Push，把标记分给两个孩子，然后递归并 Pull 父和。

区间统一使用半开形式 `[start, endExclusive)`，空区间加法是无操作、空区间求和为 0。`checked` 放在和与标记更新处，教学代码选择明确抛出 `OverflowException`，而不是静默回绕得到看似有效的错误答案。

两者选择可以概括为：数据不变、幂等查询很多时选 Sparse Table；需要区间更新时选懒标记线段树；只有单点更新和前缀和时 Fenwick 更短、更省空间。

## 33. Span 与 ArrayPool：优化必须连同所有权一起学习

`ReadOnlySpan<T>` 是连续内存的借用视图，不拥有数据。`BinarySearch` 接受 Span 后可以直接查数组切片，不需要 `ToArray()`；返回未找到时采用与 `Array.BinarySearch` 相同的 `~insertionIndex`，既表达失败又保留插入位置。

池化基数排序只租一个辅助数组，四轮在输入 Span 与租用 Span 之间交替写入。偶数轮输入到 buffer，奇数轮 buffer 回输入；四轮结束结果自然位于调用方 Span，省去最终复制。

ArrayPool 的三个重要契约：

- Rent 可能返回比请求更大的数组，只能使用需要的前缀。
- 数组可能含上一个使用者的数据，不能假定初值为零。
- 必须在 finally 中 Return；包含敏感数据或托管引用时要考虑清零。

为什么没有直接删除普通 `RadixSort`？池化有租还成本、共享池竞争和更复杂的所有权，小数组未必更快。学习项目同时保留普通版与池化版，并在 BenchmarkDotNet 的同一输入分布下比较时间和分配；只有数据证明收益且生命周期契约可控时才采用优化版。
